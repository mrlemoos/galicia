# Domain language

| Term | Meaning | Distinction |
|---|---|---|
| Context map | Navigation to relevant domain knowledge. | Links knowledge; does not copy every source. |
| Domain | Business responsibility with coherent language and ownership. | A technical package need not be a domain. |
| Spec | Agreed intended change and acceptance evidence. | Describes change, not permanent decision history. |
| Ticket | Context-sized, independently verifiable slice with explicit blockers. | A horizontal technical layer alone is usually insufficient. |
| ADR | Durable record of consequential decision, alternatives and rationale. | Superseded records remain historical evidence. |
| Review candidate | Spec with explicit lifecycle signal needing human/agent assessment. | Not proof that deletion is safe. |
| Instruction tokens | Tokens consumed by loaded skill text under named encoding. | Excludes tool results, reasoning, output and hook overhead. |
| Behaviour check | Observation against explicit task requirements. | File-size reduction cannot substitute for it. |
| Root cause | Explanation supported by reproducible failure and discriminating evidence. | Plausible hypothesis alone is insufficient. |

These terms describe engineering work. Framework and library vocabulary belongs in technical context, outside this glossary.
